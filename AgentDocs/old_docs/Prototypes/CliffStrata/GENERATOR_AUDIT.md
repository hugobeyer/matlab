# Cliff Strata generator — implementation audit

**Scope:** add a new generator; keep Rock Formation intact. Source prototypes: `CliffStrata_blocks.cl` and `CliffStrata_shape.cl`. This is a port plan, not a claim of visual/GPU parity.

## Contract and passes

1. Register a new, append-only `EMixtormatGeneratorType` value and payload in `Source/MixtormatRuntime/Public/MixtormatMaterial.h`. Follow the existing generator gather, render-data, placement, and inspector dispatch paths. Do not reuse Rock Formation's serialized enum slot or payload.
2. Blocks produces raw projected height, `block_id`, `row_id`, and `flow` (screen-space float2). Shape consumes all four internally. No user-wired textures. Translate the prototype's `-1` no-hit IDs to the plugin's invalid `uint` region sentinel when publishing IDs. Keep block and row identities separate: row ID is grid `cyi`, block ID includes phase and cell. Check repeat/copy seams before relying on either ID for downstream gates.
3. Shape needs eight ordered stages: raw 3D Voronoi; AA; horizontal directed sweep; vertical sweep; two ID-distance seed/propagation axes (seed + horizontal + vertical); final chamfer/cavities. Allocate `voronoi_raw`, `id_distance`, `row_distance`, and height ping-pong internally as RDG textures; do not expose scratch buffers as generator inputs or copyable masks. AA must read immutable raw Voronoi, not neighboring pixels from its writable output. Horizontal/vertical sweeps are *ordered scanline* operations: do not replace them with one unordered pixel dispatch. Test GPU dispatch coverage for non-square dimensions and minimum resolution.
4. Cache blocks/shape field outputs independently of layer Height Blend and preview selection. Match Rock Formation's separation of expensive field computation from cheap final height mode/scale (`MixtormatGpuGeneratorPasses.cpp`, `MixtormatGeneratorGather.cpp`). Profile phase × tile-copy × candidate-cell ray tests in Blocks and scanline passes in Shape before optimizing loops. Preserve candidate coverage and nearest-ray-hit semantics; the Rock Formation polygon field uses a different highest-height selection.

## Coordinates, height, flow, IDs

- Use `MixtormatGeneratorPlacement.ush`/existing placement parameters as the *shared* UV transform. Decide explicitly whether the prototype's projection-camera `view_scale`, yaw and pitch operate before or after placement; use the same transform for height, IDs, flow, Voronoi, and distance fields. Test tiling at both tile edges and under non-square resolution; the prototype wraps Voronoi/ID sampling, but its projected blocks are not proven tile-periodic.
- Flow is a **block-space projected direction**, not a height gradient. Pass it into the height-bent Voronoi UV warp in *both* places that would otherwise evaluate Voronoi. The new prototype caches the raw first evaluation, so final cavities/chamfer read that same raw pattern while carve/Y bias read its smoothed pattern. Keep flow zero on no-hit pixels and document how direction transforms under placement, rotation, mirroring, and scale.
- Publish final height separately from raw block height; maintain existing generator Height Blend/opacity/coverage behavior. Decide how empty pixels (raw height 0, invalid ID), negative depth range, and height normalization behave. Derive slope/normalized-height gates only after agreeing on raw vs output height, like Rock Formation's outputs stage (`MixtormatRockFormation.usf`). Do not interpret a heightfield as a signed distance by name alone.
- Block and row distance passes are **unsigned approximate seam distances**, not true Euclidean SDFs. Seed currently ignores row crossings involving background; document/test missing seams at gaps, corners, different phases, and wrap boundaries. If publishing a `SignedDistance` output, first provide a sign convention and a verified boundary field; otherwise preview distances as scalar masks only.

## Inspector, outputs, copying, previews

- Follow `MixtormatInspectorGenerators.cpp::BuildRockFormationControls`: shared blend rows, collapsible cards, enable control and `MakeChildOutputPreviewButton`. Suggested cards: **Layout** (counts/density/size), **Form** (height/lean/formation/secondary blocks), **Surface** (carve/chamfer/cavities), **Pattern** (Voronoi/flow), **View**, **Height**. Put common settings first; keep experimental controls in collapsed advanced cards. Preserve prototype defaults in the new payload until developer-authored defaults override them.
- Define capabilities in `MixtormatChildCapabilities.cpp` and publish matching named textures in the generator bundle. Start with final Height and `RegionIds` = block IDs; add Row IDs as a **distinct** published field only after checking downstream consumers support a second named ID map. Proposed copyable scalar gates: block seam, row seam, cavity, raw Voronoi, normalized height, slope, and gap/coverage **only if each has documented semantics**. Never make raw scratch buffers public by accident.
- `GetChildCapabilities` flags determine previewability and `Copy Output`/`Copy Gate` menu availability (`MixtormatLayerMenus.cpp`, `MixtormatLayerClipboard.cpp`). Existing `RegionIds` copy/ID-group rules are more restrictive than mask copying (`MixtormatLayerChildren.cpp`). Named masks must match the GPU bundle names exactly; ensure they resolve for both generator children on layers and sublayers/group-scoped instances, not just the main layer.
- Preview: height, block ID false-colour, row ID false-colour (if supported), flow direction, warped UV grid, raw/smoothed Voronoi, block/row distance, cavity mask, final height, and any published gates. Reuse `EMixtormatPreviewOutputKind` and existing flow/UV/signed-distance visualizations in `MixtormatGpuCompositor.h` rather than inventing unregistered preview kinds. Internal scratch diagnostics may be debug-only; avoid advertising unsigned distances as signed. Verify copied gates in a later layer and within scoped sublayers.

## Parameters and clamps

- **Developer-authored JSON/context-menu presets own defaults, UI ranges and snapping.** Do not add aesthetic `saturate`/`clamp` to gather, C++ setters, or shader simply to match inspector slider ranges. Preserve current prototype math unless a targeted change is tested and approved. Existing shader clamps are part of its current look; inventory them before porting instead of silently removing them.
- Keep only mathematical/resource guards: positive dimensions/cell counts, denominator epsilons, finite dispatch/buffer sizes, safe array indices and integer overflow protection. Document each guard; do not apply blanket 0..1 clamps to Voronoi strength, cavity/chamfer controls, or height/flow. Source code defaults should be sensible fallback values, with JSON-authoring overrides taking precedence (`MixtormatParameterAuthoringTests.cpp`).

## Exact prototype contract / UI mapping

- Blocks outputs: `dst` raw height (float), `flow` (float2), `row_id` (int), `block_id` (int). Optional `size_ref` is declared but **not read in the current block kernel**; do not expose it as a new generator control. Shape inputs: `src` = block `dst`, `id` = `block_id`, `row_id`, `flow`. Read/write bound layers (`&`, not output-only `!&`): `dst` final height, `voronoi_raw`, `id_distance`, `row_distance`. The OpenCL prototype requires these writable layers to exist/be bound so `.bufferIndex` works; Unreal allocates them internally as RDG textures. The `row_distance` texture **temporarily holds smoothed Voronoi after stage 1** for carve/Y bias, and is overwritten with row-distance seeds at stage 4: preserve this lifetime if aliasing RDG resources.
- Shape stages `@Iteration` **0..7**: 0 raw Voronoi (also cache raw), 1 nine-tap smoothing from raw, 2 horizontal ordered sweep, 3 vertical ordered sweep, 4 ID crossing seeds, 5 horizontal ID+row distances, 6 vertical ID+row distances, 7 chamfer and cavities. Keep synchronization between stages; a thread per pixel cannot safely run all scanlines concurrently, and the original shape sweeps assume exclusive ownership per row/column. Per-pixel ID-seed wrap uses `wrapi` and treats missing `row_id=-1` as background. Current distance is approximate, with diagonal half-pixel seeds and axis propagation, *not* a true signed SDF.
- Blocks default params (name=value): `count_x=8`, `count_y=7`, `density=0.5`, `size_min=1`, `size_max=1.35`, `size_aspect=0.95`, `jitter=0.1`, `flow_variation=0.6`, `height_min=0.025`, `height_max=0.1`, `steps=0`, `rotation=0.35`, `lean_x=0.2`, `lean_y=0`, `formation_cells=5`, `formation_amount=1`, `quarter_copies=1`, `quarter_y_count=8`, `quarter_fill=0.5`, `quarter_size=0.9`, `quarter_height=2.75`, `quarter_jitter_x=0.5`, `quarter_jitter_y=0.5`, `sides=4`, `shape_random=0`, `camera_yaw=0.5`, `camera_pitch=0.25`, `view_scale=2`, `depth_min=-1`, `depth_max=1`, `seed=1234`.
- Shape default params: `unitdist=0.3`, `unitdist_id_lerp=0.5`, `carve_depth=0.375`, `carve_voronoi=0.1`, `y_bias=0.3`, `y_bias_voronoi=0.9`, `y_bias_voronoi_invert=0`, `neg_y_unitdist_taper=1`, `dir=0`, `seed=1234`, `voronoi_cells=13`, `flow_voronoi=0`, `chamfer_width=0.5`, `chamfer_intensity=1`, `chamfer_voronoi=0.05`, `block_cavity_width=0.02`, `row_cavity_width=0.25`, `cavity_intensity=0.25`, `cavity_voronoi_threshold=0.5`, `cavity_voronoi_mask_gain=0.125`. Share the seed between blocks/shape unless product explicitly needs independent seeds.
- Suggested inspector mapping: **Layout**: counts/density, block sizes/aspect; **Formation**: heights/steps, rotation/lean, cluster and quarter copies; **Projection**: yaw/pitch/view and output depth; **Pattern**: Voronoi cells/flow warp; **Shape**: unitdist, carve depth/Y bias and their Voronoi modifiers; **Edges**: block/row cavity widths, intensity, mask threshold/gain, chamfer width/intensity. Secondary/random/advanced values can live in collapsed cards, but **keep full payload serialized and authorable**; do not discard prototype behavior to shorten UI. `Seed`, height blend, enable and preview remain in normal generator controls.
- Source projection creates the block result before shape; external placement is an additional transform and is *not* a substitute for its ray camera. Current block flow is per-hit and the height-dependent Voronoi warp (`warp_voronoi_uv`) uses raw block height and that flow. AA smoothed Voronoi drives directional carve/Y bias; raw cached Voronoi drives final mask/chamfer. Watch the prototype's `quarter_jitter_x/y=0.5` vs existing kernel's `0.48` positional clamp: **do not add new clamps** while porting, but preserve or explicitly test changes to pre-existing math.

## Height units and range — not yet calibrated

- **Do not assume prototype height already matches a 0..1 Mixtormat layer.** `CliffStrata_blocks.cl` uses `height_min/max` (currently 0.025/0.1) as **3D prism thickness in its ray scene**, but writes `dst` from nearest ray travel `best_t`, mapped through `depth_min/max` (currently **-1..1**). A miss writes **0**. These are distinct units; adjusting block thickness does not set a 0..1 output height range.
- Shape operates on that projected depth, not geometric height or a true SDF. `unitdist=0.3` and `y_bias` turn UV pixel steps `@dPdx/@dPdy` into increments in this depth scale; chamfer and cavities can push it **below the original -1 minimum**. No analytic output bounds were proven for the full shaping pipeline. Block seed `seed=1234` and shape seed `seed=1234` are paired by default.
- Mixtormat's generator module combine reads the provided float height **as-is** (`MixtormatGpuGeneratorPasses.cpp::AddGeneratorModuleCombine`, `Shaders/Private/MixtormatGeneratorBundle.usf`). `MixtormatComposite.usf::SampleIncomingHeight` can preserve live-source out-of-range floats on the direct-comparison path, but its ordinary shaped-height path uses `saturate` (around lines 639–690). Thus negative or >1 relief may be preserved or clipped depending on layer settings; do not assert universal compatibility. Rock Formation explicitly offers Raw/Analytic/Measured and a combine-only scale, while Pebbles uses 0 in gaps; neither proves Cliff's depth is normalized.
- Before porting, record min/max/mean of **raw blocks** and **shaped output** on the current defaults, empty pixels and exaggerated controls; compare under Replace/Max/Height Blend and direct vs ordinary layer height, including normal/displacement preview. Choose and document an explicit combine-only mapping (e.g. raw vs measured 0..1 and height scale) if required, without changing the cached prototype field or clamping it. Keep original raw depth and the chosen normalization available separately so masks/IDs stay aligned. A 0 background is not equivalent to no hit when valid depths may be negative: use `block_id==-1` / validity, not `height==0`, for empty classification. No test has yet confirmed a correct conversion.

## Known decisions / non-negotiable acceptance

- Minimal v1: one published block `RegionIds`, final height, and explicitly named scalar masks with real definitions; keep row IDs and flow internal if their typed publication is not implemented. Do **not** promise Row ID copying or flow debug before implementing their complete publication/preview/clipboard path. Decide which scalar masks are worth shipping; do not silently synthesize gates from unspecified ranges.
- Signed `BoundaryField` is required before enabling built-in Shape Deform / Generator Flow / Flow Carve ownership; keep that capability disabled initially unless implemented with tested inside/outside semantics. Separate internal unsigned ID distances from externally signed outline distance.
- Validate exact shader-to-prototype output across defaults and parameter perturbations, cache reuse/invalidations (including UV placement and child settings), copy output into later layer and sublayer/group, serialization, empty/background IDs, and debug target indexing. Performance targets require real GPU timings. Unverified design choices remain marked here; an implementing agent must resolve them through code/tests rather than inventing a behaviour.
