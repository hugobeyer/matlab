01

The ID Group commit — what shipped and why

The commit replaces how cluster combining is authored. The old Cluster IDs and Combine IDs nodes were two separate authoring operations with overlapping jobs: cluster coarsened an ID map, combine merged/selected between maps. ID Group collapses the "combine two maps" half into one guided node: it takes the two nearest Region-ID producers above it in the child stack, picks per-pixel between the older/macro map (Source A) and the newer/micro map (Source B) using a continuous feature signal sampled from the layer's height, and republishes the selection as a new Region-ID map. Source B wins wherever the feature clears a threshold — high areas by default, or high-curvature areas — so a macro brick layout keeps its large regions while micro detail (peel, stain, fracture) subdivides them exactly where the surface actually says so.

Three things make the design sound rather than naive:

  • Identity stays discrete. The guide (height/curvature) is continuous, but the output is always one of the two input region IDs, re-hashed with its source slot: GroupId = MixtormatRegionHash(Chosen ^ (Slot==0 ? 0x9e3779b9 : 0x85ebca6b)). Equal numeric IDs coming from different maps can therefore never collide downstream — a Pattern region 7 and a Combine region 7 become different identities.
  • Invalid-pixel fallback. If the chosen map has MIXTORMAT_INVALID_REGION at a pixel, the other source is used before the sentinel is allowed through.
  • Evaluation order is explicit. The node consumes the two nearest producers by child index; the pass scheduler keeps earlier Pattern producers alive specifically when a later ID Group would otherwise consume them.

Deprecation shape — worth knowing before you build on it

The retired authoring is a silent early-return: CreateChild returns FReply::Handled() for ClusterIds/CombineIds without any log or toast. Serialized payloads and the whole evaluation path remain live (old materials still render correctly), and Combine chains that depend on Breakup still run — only new authoring is blocked. The menu entries are gone, so the early-return is a belt-and-suspenders path, but anything that programmatically calls CreateChild with those kinds will appear to do nothing.

03

Data model

UMixtormatMaterial holds Layers (render-order array), LayerGroups (storage order only — a group's stack position is its first member's), and bake outputs (BakedBaseColor/Normal/RAM/Height, BakedMaterial, and BakedSurface — a repacked RAMH copy with DefaultIOR so a layer can source its own bake). PostLoad stabilizes binding IDs then validates groups, in that order.

Layer

FMixtormatLayer carries identity (LayerId, GroupId — membership lives on the layer, so a layer is in at most one group and nothing re-syncs when layers move), source (SourceSurface or a live SourceComposition reference to another material), channel mode (complete surface / normal-detail), surface overrides, UV placement, color adjustments, and the height-blend block. Two recurring invariants are enforced by convention and documented in-place:

  • The frac() domain. Every source read is wrapped in frac(), so UV transforms must map the unit square onto itself: per-axis scale is integer (1–16), rotation is quarter-turns only, offset/flip are free. Applied flip → rotate → tile, so the texture turns and the lattice replicates the turned result.
  • Normal strength vs height boost. NormalIntensity is the authored map's tangent-slope gain; HeightBoost owns the height field only, and derived passes get boosted height once by differentiation (MixtormatReliefScaling.h keeps tripwire functions so the two can't be conflated again — the header comments record that they once were, double-counting the same bump).

Children — the whole node vocabulary

FMixtormatLayerChild is a flat tagged union: Type selects exactly one payload struct. Every dispatch in the plugin switches on Type alone. Children also carry ScopeOwnerChildId (scoped beneath another child, gating only its owner) and whole-child instancing (SourceLayerId/SourceChildId, payload re-read from source every composite).

Groups

FMixtormatLayerGroup stores one authored child stack that broadcasts. MixtormatLayerGroups::BuildEffectiveLayers is the only place groups exist: it copies the layer array, ANDs member enable with group enable, and appends group children after local children with derived, deterministic per-member child IDs (MakeEffectiveChildId). Everything downstream sees a flat array. ValidateGroups keeps each group's first contiguous run and ungroups strays rather than reordering a user's stack.

04

Parameter system — reflection first, contracts sparse

The system deliberately avoids a hand-maintained master table. Identity, type, default, family and UI ergonomics are discovered from reflection: the UPROPERTY's name, type, CDO initializer, Category and UIMin/UIMax/Delta meta. Only what the shader implies and reflection cannot express lives in the runtime MixtormatParameterContracts table (FMixtormatParameterContract: HardMin/HardMax, NormalizationScale, bShaderSaturates) — and a parameter without an entry is legal, not an omission. Contracts must be runtime code because packaged builds strip editor meta, and the compositor sanitizes with them in every target.

  • Sanitization is one path: SanitizeFloat — non-finite falls back to the reflected CDO default, then HardMin/HardMax clamp. Defaults never need a second copy of the number.
  • Bindings (FMixtormatParameterBinding) address parameters by FMixtormatParameterAddress (Owner type + FName), support direct references and scalar drivers. Only two driven scalars exist today (RoughnessInfluence, HeightBlendAmount), sourced from CombinedMask or RegionIds; a driver that can't resolve contributes nothing and the authored value survives.
  • Authoring side (MixtormatParameterAuthoring, MixtormatParameterUiMeta, MixtormatShaderParamScanner): persistent authoring defaults, UI metadata tables, and a scanner that reads the .usf files so drift tests can verify shader ↔ C++ ↔ contract agreement (commits 30c1f1e, 0f9277e made dev metadata default-on).
05

GPU compositor pipeline

Game thread — gather (MixtormatGpuCompositor.cpp)

  • RequestCompose validates live-composition references (MixtormatCompositionReferences::Validate — depth 32, self-reference even through redirectors, cycles), then RequestComposeInternal.
  • Groups expand once, here and nowhere else. Preview targets (FMixtormatChildPreviewTarget: OwnerId, ChildId, OutputName, Kind, GapMaskName) resolve by GUID to LayerIndex/ChildIndex exactly once; every pass uses IsChildOutputPreviewTarget.
  • Reference layers (SourceComposition) recurse through a fresh stack-allocated child compositor per occurrence — own IDs, own ping-pong, own drivers — depth-limited and cycle-checked; the child's published targets ride along as SourceOutputs.
  • Per layer: direct reference application, source texture resolution (static-cached engine whites/normals), scalar-driver extraction, then the child gather loop — one branch per child type, each with its own clamp set and disabled-layer policy. Mask children still resolve on disabled layers so others can reference them; effects, generators, UV/relief/ramp filters don't gather on disabled layers because each would otherwise cost work nothing can see.

Render thread — the graph (MixtormatGpuComposePipeline.cpp)

per composite ├─ register 6 output pairs (BC / N / RAM / Height / Debug / RegionIdPick) ├─ clear Debug + RegionIdPick of the published half (picker sentinel = −1) ├─ 1×1 dummies: EmptyRegionIds(0xffffffff) · EmptyPatternUV(.5) · EmptyPatternOrientation · EmptyDriverSignal ├─ seed substrate into BC/N/RAM/Height[1] // layer 0 writes half 0, reads half 1 ├─ per-graph ping-pong pairs, both halves cleared: Mask(R16F) · Ridge · Effect(RGBA) · EffectHeight(R16F signed) ├─ per layer (WriteIndex = LayerIndex & 1): │ ├─ AddRegionProducerPasses // Cluster / Pattern / Combine / IdGroup → RegionIdMaps, sorted by child idx │ ├─ AddUvIdPasses // per-region source-UV rewrite, before any source read │ ├─ AddLayerHeightSmoothPasses │ ├─ AddGeneratorPasses // rewrites LayerInputHeight/N in place — pre-mask, pre-composite │ ├─ child loop // masks, craquelure, random/color IDs, effects (some queued pending) │ │ CombineId producer runs at its authored row // breakup-dependent chains become available here │ ├─ CollectPendingRampTilts │ ├─ [bPrepareStructure] isolate Local BC/N/RAM/Height when Breakups or Fracture exist │ ├─ AddLayerCompositePass // height contest, normals, HSV variation, grades, pattern UV │ ├─ deferred: Erosion → RampRelief → Fracture → CraquelureRelief → Breakup → WornEdges │ ├─ [structure-prepared] second AddLayerCompositePass with the carved channels as input │ └─ AddLayerBlurPasses // last — nothing may sharpen what blur was asked to remove └─ publish: PublishedTargetIndex = (LayerCount−1) & 1 // bRotateOutput90 swaps the published half

Design decisions worth internalizing before touching this file:

  • Layer 0 is not special. The substrate is cleared into half 1, so layer 0 composites onto it exactly like every other layer composites onto its predecessor. Comment history: when layer 0 seeded its own buffers it ignored its own mask/feature/height-blend, so a layer couldn't be dragged to the bottom without changing what it did.
  • RDG validates bindings, not uses. Hence both halves of every ping-pong pair are cleared, and 1×1 dummies fill every conditional slot. The ensure-once RDG errors this avoids are recorded in comments.
  • The erosion ridge pair ping-pongs across layers (drainage + crest lines): a generated mask on layer N sees accumulation below N, and non-eroding layers copy read→write so nobody inherits a stale ridge from two layers back.
  • Height snapshots are demand-driven — only layers actually named by another layer's HeightReferenceLayerIndex get their height copied aside.
  • Network cache (FMixtormatNetworkCache): craquelure propagated distance fields only, keyed by FNV-1a over exactly the parameters growth reads (everything post-field is deliberately excluded so slider drags hit), byte-bounded at 512 MB, LRU. Render-thread-only, shared with in-flight requests.
  • Effects that modify the finished surface are deferred past the composite (Erosion, Breakup, WornEdges, craquelure/ramp relief, fracture); effects that only shape the layer's mask run in the child loop. Stain and Runoff write their own debug previews because the composite would otherwise overwrite them.

The composite kernel (MixtormatComposite.usf)

Three entry points: ResolveLayerInputCS (per-layer source resolve incl. UvFromIds), ResolveLayerValuesCS (albedo+HSV/roughness signature other nodes read), and MainCS — the ~50 KB heart that does the height contest (SampleHeightBlendFieldEx, contact/border fields with pre-smoothed texture feeds), normal decode + RNM combine, per-region HSV variation, up to 8 grades, fill/coat modes, and all debug modes. The pre-smoothing rationale is documented: blurring the field in a texture beats widening the derivative, which reaches further into noise instead of averaging it.

06

The Region-ID contract

MixtormatRegionId.ush is the single source of truth: the MIXTORMAT_INVALID_REGION sentinel (0xffffffff — currently never written, union-find gives every pixel a root, but consumers must decide), the murmur-style MixtormatRegionHash, the multiply-decorrelated MixtormatRegionSeed (adjacent regions carry numerically adjacent IDs; a plain xor would show a visible gradient), and ~16 named salts so one region's height, feather, bevel, UV draw, gap and slide all move independently under one Seed control. One file because a preview coloured from a drifted copy of the hash would not match the variation it previews.

Producers → RegionIdMapsConsumers
ClusterIds (union-find coarsen) · PatternIds (grids, fracture plates, boundary randomness) · CombineId (merge/selection; breakup-dependent chains) · IdGroup (guided two-source pick — new) RandomId · RampId · HsvFilter · ColorId Exact-ID mode · UvFromIds · ReliefFromIds · RampIdRelief (+EdgeShade) · RegionIds drivers · RegionIdPick (Exact ID picker reads the raw map only while its preview is up)

Consumers ask for "the nearest valid map above me" and never which node produced it — Pattern, Cluster, Combine and now ID Group are equally valid sources. Publication is kept sorted by SourceChildIndex; ID Group's AddIdGroupPasses walks that array and keeps the last two entries below its own index. A producer whose only purpose is to feed a later ID Group is force-kept alive even if nothing else would want it. The "Boundary" mask ID Group publishes joins the same named-mask publication channel (FPublishedMaskKey) that Breakup's Gap/Edge/Pieces and Worn Edges' Wear use — one mechanism, addressed by name.

08

Effect pass layer — one authoring pattern, ~40 passes

Every effect follows the same shape: an FGlobalShader class with a FParameters struct, an IMPLEMENT_GLOBAL_SHADER pointing at a .usf entry point, an Add…Passes/Add…Pass function per family, and a gather function in Compositing/MixtormatEffectGather.cpp that sanitizes authored values through the contract table before they reach render data. Families: GpuEffectPasses (Erosion 2.9k lines incl., Craquelure×5, Grade, FlowWarp×3, Breakup×4, EdgeWear, LayerBlur, EffectMerge, CarveShade, HeightDeltaNormal), GpuPatternPasses (Cluster, Pattern, Combine, Random, Ramp, UV, EdgeShade, ID Group, region JFA set), GpuMaskPasses (Mask/Resolve/Merge, ColorId, Generated, Blur, Curvature, height-smoothing blurs), GpuSimulationPasses (Peeling, PeelField, Stain), GpuRunoffPasses (Downsample/Prepare/Resolve/Apply), GpuGeneratorPasses (StrataCarver×4), GpuFracturePasses (Topology/Seed/Step/Field/Resolve), GpuDebugPreviewPasses (mask blit, region-ID colourist, RegionIdPick).

Notable per-family state: Erosion is a momentum slope/curvature solver rewritten across four commits (steering → momentum solver → downhill transport → gravity rework) and publishes the ridge pair; Breakup authors structural IDs during child collection but applies relief after the composite, deliberately ordered before Worn Edges so wear reads real plate boundaries; PeelField relief is signed around zero so stacked peels accumulate.

09

Editor architecture

SMixtormat is one widget class split across focus files: SMixtormat.h (67 KB — the class contract), _Shell (layout, tabs, theme wiring), _Document (undo/transaction model, asset save/load, bake entry), _Layers (255 KB — rows, groups, drag-drop, child creation incl. the retired-authoring early-return), _Inspector (270 KB — per-type control builders, now including BuildIdGroupControls/BuildIdGroupFeatureMenu), _Parameters (driver + parameter-authoring UI), _Preview (viewport + debug-preview menu), _Library (surface/mask gallery), _Theme (live theme). Supporting services: MixtormatLayerPreview (isolated per-layer composites so the preview shows one layer against the substrate), SMixtormatPreviewViewport + light gizmo, MixtormatThumbnailRenderer, MixtormatSurfaceImporter (44 KB import path), MixtormatRegistry/Paths/AssetMigration, MixtormatBakeService (bake → textures + repacked RAMH UMixtormatSurface), bake dialogs, and gallery cards. A child-addressing (MixtormatChildAddress.h) and child-capabilities module decouples rows from concrete child types.

Fragile spots & conventions to respect

SpotWhy it bites
Enum serialization is by valueEvery child-type / blend-mode / height-source enum is append-only. Inserting above the marked line silently retypes every saved asset. The rule is restated in comments at each site — keep obeying it.
ID Group needs two producers above itAddIdGroupPasses returns null when fewer than two earlier maps exist — silently, no log, no preview explanation. An ID Group placed at the top of a stack does nothing with no diagnostic.
Retired authoring early-returnCreateChild swallows ClusterIds/CombineIds clicks (Handled(), no warning). Fine for UI (menu entries removed), a trap for programmatic callers.
Grade hard limitMore than 8 Grade effects on one layer fails the whole compose (return false), not a fallback. Deliberate, but user-visible as "preview stops updating".
ID Group feature costSmoothedHeight is a full (2r+1)² tent per tap; Curvature mode evaluates it 5× per pixel (r=2 → 125 samples/px, r=8 → 405). Unmeasured — flagging as a candidate cost center, not a confirmed problem.
Rotate outputRequires square resolution; rejected otherwise with no UI surface explaining why.
Ping-pong paritySubstrate in half 1, WriteIndex = LayerIndex & 1, ridge pair copy rules, published-half swap on rotate — all correct today and all easy to break by adding a pass that reads the wrong half. The comments in MixtormatGpuComposePipeline.cpp are the spec; read them before touching scheduling.
Network cache budget512 MB byte-bounded LRU on craquelure distance fields; 4K entries are 268 MB each, so one 4K network evicts everything else.
Group broadcast orderGroup children append after local children. ID Group inside a group sees the member's local producers — consistent, but "nearest above" jumps the local/group boundary at a fixed place.
