Mixtormat / Artist Documentation

Layer, mix, weather, and finish materials inside Unreal.

Mixtormat is a GPU-driven material compositor built around an artist-friendly layer stack. It combines complete PBR surfaces, masks, height-aware blending, procedural effects, region IDs, parameter links, and a live Unreal preview while keeping the material editable as a recipe until you bake it.

Overview

The main idea is simple: treat a material like a stack of surfaces rather than a single finished texture set. A stone base can receive plaster, paint, rust, dust, stains, cracks, peeling, or other treatments without flattening those decisions into one irreversible result.

Each material layer can contribute several channels at once. Mixtormat then combines the channels, masks, and effects in the order shown in the layer stack. The preview is the current GPU-composited result; the saved Mixtormat asset is the editable recipe; the bake is the final set of Unreal assets.

Complete PBR SurfacesWork with Base Color, Normal, Roughness, Ambient Occlusion, Metallic, and Height as one surface instead of rebuilding each channel separately.
Height-Aware MixingLet raised and recessed areas influence where materials meet instead of relying only on flat opacity.
Ordered Masks & EffectsA layer contains a readable sequence of masks, generated regions, filters, IDs, and effects.
Non-Destructive RecipesSave the whole setup, reopen it, reorder it, change values, branch variants, and bake again.

A useful mental model
Materials define what the surface is. Masks define where something happens. Effects define what changes. IDs define which regions can behave differently.

Quick Start

1. Pick a material from the Library

Browse by family or search by name. Selecting a surface lets you inspect it before it becomes part of a recipe.

2. Drag the surface into Layers

Dropping a surface into an empty stack starts a new Mixtormat material. Dropping another surface adds a new material layer.

3. Decide how the layers should meet

Start with layer order, tiling, composition mode, channel influence, and Height. Then add a mask if the upper material should only appear in specific areas.

4. Add breakup

Add texture masks, Generated Masks, region IDs, or procedural tools. Use these to keep wear from being perfectly uniform.

5. Add effects

Use Grade, Stain, Erosion, Procedural Peeling, Chipping, Worn Edges, Craquelure, or other available effects to push the surface toward the intended history.

6. Check the Preview

Switch between Sphere, Plane, and Cube, change lighting, compare Before / After, inspect masks and IDs, and enable displacement when Height matters.

7. Save, then Bake

Save the recipe first. Bake when you want regular Base Color, Normal, packed material data, Height, and a Material Instance for production use.

Workspace

Mixtormat keeps the authoring view divided into a few permanent jobs instead of spreading controls across many windows.

Left — Layers / LibrarySwitch between the current recipe and the searchable surface library.
Center — PreviewJudge the current composite on a simple look-development mesh.
Right — InspectorEdit whichever layer, mask, generator, ID node, or effect is selected.
Bottom — Materials / MasksKeep reusable surfaces and masks close while building the stack.

Resizable layout

The primary columns and the center preview/library split can be resized. The bottom Material and Mask galleries can also be collapsed to give the preview more room — press G to toggle them, the same idea as H for the viewport overlay.

Top bar

The main document actions live at the top: Undo, Redo, New, Load, Save, Save As, and Bake. The current material name and edited state remain visible while you work. DOCS opens this documentation, and SETTINGS opens the Mixtormat preferences described below.

Settings

Mixtormat's preferences live in Editor Preferences → Plugins → Mixtormat, reachable directly from the SETTINGS button in the top bar. They cover the bake defaults: Default Resolution and Default Output Path (/Game/Mixtormat/Baked unless changed). These are starting values for the Bake dialog only — changing the destination or resolution for a single bake never writes back to them.

Status bar

The bottom status area reports the current working state, preview quality, rendering mode, and layer count. It is useful for confirming whether a recipe is saved and what preview mode you are judging.

Material Library

The Library is the source browser for reusable Mixtormat surfaces. Surfaces are grouped by family and shown as visual tiles so the normal workflow is browse → inspect → drag, rather than search through raw texture assets in the Content Browser.

Categories and search

Choose a category to narrow the library, or search by material name. The category list is rebuilt from the surface families currently available to Mixtormat.

Preview before using

If no recipe is being edited, selecting a surface previews it directly. This makes the Library useful for comparing source materials before committing one to a stack.

Gallery zoom

Hold Ctrl and use the mouse wheel over a material or mask tile to change the gallery tile size. Smaller tiles are useful for scanning a large library; larger tiles are better for evaluating a surface visually.

Drag into the stack

A library surface can be dragged into Layers. In an empty document it becomes the first layer. In an existing recipe it is added as another Material Layer.

Importing Surfaces

For artists preparing custom source sets, Mixtormat expects the channels of a surface to agree as one material. The current source convention uses matching names with channel suffixes.

_BCRGB Base Color. This is the color texture and is treated as sRGB data.
_NRGB tangent-space Normal.
_RAMR = Roughness, G = Ambient Occlusion, B = Metallic.
_RAMHSame RAM packing, with A = authored blend Height.

RAM versus RAMH

Use RAMH when the source contains an authored height field intended for material blending. A normal RAM texture does not treat its alpha as Height.

Reusable masks

Reusable masks are grayscale data rather than PBR surface sets. For source masks, use lossless linear grayscale data rather than sRGB color data.

Why the naming matters

The importer needs to recognize which textures belong to the same surface and which role each file plays. Keeping one shared base name makes the set unambiguous.

Where imports land

Imported surfaces and masks go into your project content at /Game/Mixtormat/Library — surfaces under Surfaces/, masks under Masks/, raw textures under Textures/. Nothing is written into the installed plugin, so your own imports survive reinstalling or updating Mixtormat, and they travel with the project rather than the engine install. The Library browser reads both roots at once, so built-in and imported content appear together.

Layer Stack

The stack is the actual material recipe. Layers are evaluated in order, and each layer can contain an ordered list of children such as masks, effects, generated masks, IDs, and filters.

Selecting and reordering

Click a layer to edit it in the Inspector. Drag a layer row to reorder it. The first layer is not a permanently locked “base” layer; layers can be moved and the stack can even be emptied.

Visibility

The eye icon enables or disables a layer. Use Ctrl or Alt while clicking the eye to solo that layer in the preview.

Layer children

Expand a layer to see its children. Children can be selected, enabled or disabled with their status control, reordered by dragging, moved between compatible layers, duplicated, copied, instanced, or removed.

Right-click menus

Right-click a layer or child for its context actions. This is where duplication, removal, copy/paste, instance operations, and other structure-level commands live.

IMAGE — Expanded layer with multiple child types and the layer context menu open.

Layer Types

Material Layer

A complete source surface from the Library. This is the usual choice when combining real PBR materials such as stone + paint, metal + rust, plaster + brick, or clean + damaged variants.

Fill Layer

An artist-authored layer for simple material values. Fill layers can override properties such as Base Color, Roughness, Metallic, and IOR without requiring a full source texture set.

New layer versus child effect

Effects are not a layer type — they are children you add to an existing layer. Add a new Material or Fill Layer when a different physical surface is being introduced; add a child effect when the surface already in the stack is being changed. Keeping that distinction usually makes complex stacks easier to read later.

IMAGE — Side-by-side examples of Material and Fill layer rows, and a layer with child effects.

Composition & Channels

Mixtormat does not have to treat every layer as one fixed all-or-nothing blend. The layer controls determine both how the surface composes and which material channels should contribute.

Composition mode

ReplaceThe incoming layer replaces the underlying contribution according to its mask and blend controls.
CoatTreat the layer more like material sitting over another surface, useful when the underlying surface relationship should remain perceptible.

Complete Surface

Use Complete Surface when the layer represents a full material and should contribute the normal PBR channel set together.

Normal Detail

Use Normal Detail when a layer is mainly adding normal information rather than replacing the whole surface. A standalone Normal texture can also be used as the normal source.

Normal blending

Combine (RNM)Combines tangent-space normal detail while preserving the orientation of the surface below.
OverrideUses the incoming normal as the replacement in the affected region.

Channel influence

Channel influence lets a layer affect some properties more than others. For example, you may want a dust layer to change Base Color and Roughness strongly while barely changing Normal or Height.

Roughness and normal adjustments

Layer-level controls include roughness bias/contrast/offset and normal intensity. These are useful for matching two source materials before adding more complicated effects.

IMAGE — Inspector showing Composition, Channel Influence and Normal controls.

Height System

Height is one of the main differences between a flat opacity mix and a material transition that feels physically layered. Mixtormat can use Height as part of the relationship between an incoming layer and the surface below it.

Height sources

RAMH HeightUses authored Height stored in the alpha channel of a RAMH source.
Mask as HeightUses the accumulated layer mask as the height signal.
Constant HeightUses a uniform artist-set height value.
Layer HeightUses height information from another layer in the current recipe.

Why relative height matters

Height blending is most useful when the two materials have a believable relationship. Paint may sit above a rough wall but sink into pores. Dirt may collect in recesses. Mortar may sit lower than brick faces. The correct result often comes from adjusting the relative heights before adding more noise to the mask.

Height and the preview

The composited Height can also drive preview displacement. Use this to check whether a blend reads as a real surface from a glancing angle rather than only from the front.

IMAGE — Same blend shown as flat mask versus height-aware blend, plus displaced preview.

Masks

Masks define coverage. They can be texture-based or procedural, and several masks can be combined in sequence under one layer.

Mask shaping

Balance, Contrast, Offset, and Invert reshape the mask without changing the source texture. Use these before stacking additional masks when the source is already close to the region you want.

Placement controls

Masks support separate X/Y tiling, UV offsets, U/V flips, and 0°, 90°, 180°, or 270° rotation. Quarter-turn rotation keeps tiled masks predictable at their repeat boundaries.

Mask weight

Weight controls how strongly that mask operation participates in the accumulated result.

Mask blend modes

Replace / Add / SubtractDirectly replace coverage or add/remove regions.
MultiplyIntersect the current coverage with another mask.
Min / MaxKeep the lower or higher value between masks.
Add/SubUse a centered add/subtract style operation.
OverlayContrast-like combination that preserves more structure from both masks.
Difference / ExclusionCreate alternate overlap relationships useful for procedural breakup.

Scoped masks

An Effect can own a mask of its own. This means the effect can be localized without changing the entire layer mask—for example, a stain only in one region of a painted layer.

IMAGE — One texture mask with shaping controls, then three mask blend-mode examples.

Generated Masks

A Generated Mask builds coverage from information already available in the material instead of requiring a painted texture. It is useful for effects that should respond to the shape or structure of the surface.

Curvature

Curvature can favor convex or cavity regions. Use it for edge exposure, worn corners, recessed buildup, or any mask that should respond to changes in the Normal field.

Direction

Directional weighting favors surface orientation in a chosen tangent-space direction. Angle and broadness control where the directional response points and how tightly it is focused.

Ambient Occlusion

AO weighting is useful for grime, dust buildup, dampness, or other effects that should prefer occluded areas rather than exposed faces.

Height

Height weighting lets coverage prefer higher or lower parts of the current surface structure. Combined with curvature and AO, it can create more believable placement than any one signal alone.

Combining signals

Generated Masks use signal weights, so several cues can contribute at once. A practical example is “mostly cavities, slightly biased by height, with a small directional influence.”

IMAGE — Generated Mask with Curvature, Direction, AO and Height debug examples.

Region & ID Tools

ID tools divide a surface into discrete regions. Unlike a soft grayscale mask, every region can have a stable identity. This is useful when you want variation per brick, stone, flake, tile, crack island, or procedural cell.

Color ID

Build regions from color information. This is useful when an authored ID texture or color-coded source already contains the segmentation you need.

Cluster IDs

Cluster a surface into region labels instead of producing soft coverage. Because the result is discrete IDs, it is intended to feed later ID-aware variation rather than behaving like a normal mask.

Pattern IDs

Create structured, tileable region layouts. Pattern IDs are useful for materials such as masonry, tiles, panels, paving, or any surface where a repeated construction pattern should drive per-piece variation.

Random From IDs

Turn each region ID into a repeatable random value. This is ideal for small per-piece changes without noisy variation inside each piece.

HSV From IDs

Use IDs to vary hue, saturation, and value per region while keeping each region internally coherent.

Ramp From IDs

Turn region IDs into gradient/ramp information for ordered variation, relief shaping, or downstream control.

Why IDs are useful
If every pixel receives different noise, the material looks noisy. If every region receives a different value, the material can look assembled from different physical pieces.

Effects

Effects modify material information already in the recipe. Some are straightforward adjustments; others generate their own fields from Height, Normal, masks, or region data.

GradeColor and tonal correction.
StainLocalized discoloration and surface buildup.
ErosionDirectional/gully-style wear driven by existing surface structure.
Procedural PeelingGrow and shape lifted or detached material regions.
ChippingBreak edges or surface regions into chipped damage.
Worn EdgesTarget edge wear and exposed regions.

Effect order

Effects are evaluated in sequence. A Grade before a Stain does not necessarily produce the same result as the Grade after it. Height-changing effects can also change what later effects see.

Bypass while judging

Select a child and use Bypass child in the preview to temporarily remove it from the live composition without deleting or disabling it in the saved recipe.

IMAGE — One layer with several effects and Bypass child enabled for the selected effect.

Procedural Peeling

Procedural Peeling is for material that separates from the surface below: old paint, coatings, plaster, labels, thin crusts, or similar layered damage.

Source mask

The peel can use its own Peel Mask. If none is assigned, it can fall back to the layer's accumulated child mask. Mask tiling, inversion, gain, and threshold define the initial peel contour.

Growth

Growth can respond to Convexity, Occlusion, and Height. These signals bias where peel propagation is more likely rather than producing a completely uniform expansion.

Flakes

Lift Variation and Size Variation break the peel into less uniform pieces. Flake Cells controls the larger segmentation scale. Peel type can be Flat or Curled.

Use it as a layered effect

Peeling works best when the underlying and upper materials make sense together. A peeling paint layer over bare metal or plaster has a clear height and color relationship; a peel effect alone cannot create that material story.

IMAGE — Procedural Peeling Inspector and a close-up showing flat versus curled flakes.

Erosion

Erosion is intended for structured wear rather than simple domain-warp noise. It uses the existing surface and directional/gully information to create breakup that can follow ridges, creases, and broader material structure.

Scale and period

Period controls the coarse repeated structure across the UV tile. Keeping the period integral preserves seamless tiling.

Gain and detail

Gain controls the strength of the procedural field, while Detail changes how strongly existing ridges and creases suppress or reveal finer erosion structures.

Gully weight

Gully Weight controls how strongly the directional gully component participates. Use it when erosion should read as flow or directional wear rather than isotropic breakup.

Normalization

Normalization can restore weaker blended structures without forcing every cancellation point into an equally strong feature.

IMAGE — Erosion at low/high gully weight with Height or Normal debug view beside it.

Stain

Stain adds localized discoloration and buildup while remaining part of the editable effect stack. It is useful for dirt, moisture marks, rust staining, runoff, soot, and other surface history.

Start from placement

The most important choice is where the stain belongs. Use a child mask, an effect-local mask, or a reusable stain mask before pushing color or intensity.

Height-aware distortion

Stain can use Height to distort or influence its result, helping it follow surface structure instead of looking like a decal placed over the material.

Build multiple scales

Large stain shapes establish the event; medium breakup creates pooling and unevenness; smaller variation prevents the edge from looking computer-clean.

IMAGE — Stain mask, stain effect controls and final shaded result.

Chipping & Worn Edges

Chipping and Worn Edges cover related but different types of damage. Use them according to whether the surface is losing chunks/material or simply exposing high-contact edges.

Chipping

Chipping is suited to broken paint, concrete, stone, plaster, coatings, and other materials where the damaged region needs more irregular depth and breakup.

Worn Edges

Worn Edges is suited to contact wear and exposed convex regions. It is especially useful when a clean manufactured or painted object needs the edges to read as handled or abraded.

Combine with masks

Neither effect needs to be applied everywhere. Restricting the effect with a Generated Mask, texture mask, or region-based driver usually gives a more believable result than simply lowering global strength.

IMAGE — Chipping and Worn Edges shown on the same base material for comparison.

Grade

Grade is the general-purpose color correction stage. Use it to make a source material fit the current art direction without editing the original texture set.

Correct before adding complexity

If two materials feel disconnected because one is too warm, saturated, dark, or bright, fix that relationship before adding extra procedural breakup.

Local grading

Because Grade can live as an ordered effect, it can be masked and positioned in the child stack. This makes it useful for localized fading, discoloration, or per-region variation as well as whole-layer correction.

IMAGE — Grade controls with original and corrected material side-by-side.

Craquelure

Craquelure creates crack networks that can be used as coverage and as surface relief. It has two different generation approaches depending on whether you want a cell-wall pattern or actual propagated fracture behavior.

Lattice mode

Lattice measures distance to Voronoi-style cell walls. Scale controls the size/count of pieces, Jitter moves from regular construction-like cells toward more organic crazing, and Width controls the crack thickness in cell-relative units.

Propagated mode

Propagated mode grows cracks through procedural stress, toughness, and flow fields. Density controls how many cracks begin; Reach controls how far they can travel. Detail, Contrast, Straightness, Fracture Bias, Flow, Roughness, Threshold, and Collision control the character of the growth.

Relief

Craquelure can cut into composited Height and derive Normal response around the groove. Height controls the cut depth, Normal controls how strongly the groove catches light, Groove controls its wider depression, and Profile changes the wall shape.

Warp

Warp bends the finished crack network with periodic curl-style variation while keeping the result tileable.

Blend

The crack network can combine with the mask accumulated above it using the normal mask blend modes, followed by the same shaping controls used by texture masks.

IMAGE — Lattice versus Propagated Craquelure, plus a close-up of crack relief.

Parameters

Most numeric controls in Mixtormat are scrub-style fields built for fast material iteration.

Scrubbing

Drag horizontally with the left mouse button to adjust a value. Hold Shift while dragging for fine adjustment. Hold Ctrl while dragging to snap to the parameter's step.

Typing exact values

Click a numeric field without dragging to enter a value directly. Press Enter to commit it. Escape leaves text-entry mode without applying the edited text.

Reset to default

Middle-click a numeric control, or hover it and press Backspace, to reset that parameter to its default value.

Modified values

Changed controls are visually marked so it is easier to scan an Inspector and see where the selected item differs from its defaults.

IMAGE — Numeric control showing normal, modified, scrubbed and text-entry states.

References & Drivers

Mixtormat parameters do not have to remain isolated values. A parameter can reference another parameter or be driven by procedural data from the recipe.

Parameter references

Right-click a compatible parameter to access reference actions. Copy a parameter reference, then paste it onto another compatible parameter.

Follow SourceOne-way. The destination reads the source value. Editing the destination locally breaks the reference.
Link ValuesTwo-way editing behavior. Both controls represent one linked value and edits continue to write to the source.

If the reference source disappears, Mixtormat marks the reference as broken and falls back to the local value rather than leaving the parameter unusable.

Drivers

A Driver modulates a parameter using material data rather than copying another parameter. Driver sources include the Layer Mask, a Child Mask, or Region IDs.

Driver combine modes

The driven signal can Replace, Multiply, Add, Subtract, Min, Max, or Lerp with the parameter. Input and output ranges let you remap the signal, and it can be inverted.

ID-driven values

When Region IDs are the source, the driver can use a repeatable random value per ID, target a specific ID, or work over an ID range. This makes one parameter vary per procedural piece without creating a separate layer for every piece.

Example
Pattern IDs can define individual bricks. A Region ID Driver can then vary a Grade or Roughness parameter per brick while each brick stays internally consistent.
IMAGE — Parameter context menu, Follow/Link control, and a Region ID Driver example.

Instances & Reuse

Layer children can be copied either as independent copies or as live instances. This is useful when the same procedural setup needs to appear in several places without manually matching every parameter.

Copy / Paste

A normal Copy and Paste creates another child that can be edited independently.

Copy as Instance / Paste Instance

An instance keeps a relationship to its source child. Use this when several layers should share the same mask, generated setup, ID tool, or effect configuration.

Instance actions

Instance context actions include Go to Source, Break Instance, Replace Instance Source, and Copy Instance Reference. These help manage larger recipes where the same authored child is reused repeatedly.

When to use an instance

Use an instance when the repeated setup should remain synchronized. Use a normal copy when the new child is only a starting point and should immediately diverge.

Preview

The Preview is a dedicated Unreal look-development viewport for the current GPU composite. It is meant to help judge the material as a surface, not only as a set of texture channels.

Preview meshes

Switch between Sphere, Plane, Cube, and Cylinder. A plane is useful for tile structure and patterns; a sphere makes roughness and normal response easy to read; a cube exposes edge behavior; a cylinder shows how a pattern wraps and where tiling seams land on a curved surface.

Lighting presets

Available studio lighting presets are Neutral, Soft, Dramatic, Rim, and Workshop. Light and skylight intensity can be adjusted without losing the character of the selected preset.

Before / After

Before shows the base state before added layers are composed. After shows the complete stack. Use this frequently when many subtle operations have accumulated.

Bypass child

Temporarily removes the selected Mask, Generated Mask, or Effect from the preview only. It is useful for A/B checking one operation without changing the saved recipe structure.

Debug views

Feature-preview controls can show information such as the selected Layer Mask or Cluster IDs directly. Use these when the shaded result does not make it obvious whether a problem comes from region selection or from the effect using that region.

Channel preview

Press V with the preview focused to cycle a raw, unlit view of one composited output at a time: Material (the normal shaded result) → Base Color → Normal → Roughness → AO → Metallic → F0 → Height, then back to Material. This is a diagnostic view with no toolbar control — it shows the channel exactly as it was composited, with no lighting applied, which is the quickest way to tell whether a problem is in the channel data or in how it is being lit.

Displacement

Enable displacement to judge the composited Height as geometry. Displacement Amount controls how strongly Height moves the preview surface.

Quality

Preview quality has Low, Medium, and High modes. Use a lighter mode while rapidly scrubbing expensive stacks, then return to higher quality for final look-development checks.

Anti-aliasing

FXAASingle-frame and stable while moving. It is useful when judging thin masks or cracks that can shimmer under temporal accumulation.
TSRTemporal Super Resolution. Better at resolving thin detail in a settled view, but history needs to reconverge after camera movement or a recomposite.

Screen Percentage

The preview render scale ranges from 75% to 200%. Values below 100% reduce fill cost; values above 100% provide real supersampling for shader and texture detail.

Camera

FOV can be adjusted from 20° to 90° and defaults to 40°. A Reset action restores the default camera and lighting state.

Baking

Baking converts the current editable recipe into regular Unreal assets. The recipe must be saved before a bake begins.

Bake resolution

The Bake dialog has its own Resolution control, offering 512, 1024, 2048, and 4096. It is independent of the preview's composition resolution (1024, 2048, 4096), so you can work against a cheap preview and still bake at full size without changing how you were judging the material. The bake composites at the chosen resolution and restores the preview afterwards.

The starting value comes from Default Resolution in Editor Preferences → Plugins → Mixtormat. Picking a different resolution for one bake does not change that default.

Bake outputs

Base ColorThe composited color output.
NormalThe composited tangent-space Normal.
RAMPacked Roughness, Ambient Occlusion, and Metallic data.
HeightThe composited height output.

The bake also creates the Material Instance that uses the generated outputs.

Destination and naming

The Bake dialog lets you choose the destination folder and a base name. These are remembered for the current recipe, so repeated bakes do not require rebuilding the destination each time. The dialog previews the exact asset names before you commit.

For a base name of Rock_01, a bake writes five assets into the destination folder:

T_Rock_01_BCBase Color.
T_Rock_01_NTangent-space Normal.
T_Rock_01_RAMPacked Roughness / AO / Metallic.
T_Rock_01_HHeight.
MI_Rock_01The Material Instance wired to the four textures above.

The default destination is /Game/Mixtormat/Baked, set by Default Output Path in Editor Preferences → Plugins → Mixtormat.

Updating an existing bake

If output assets already exist, Mixtormat asks before updating them in place. This lets existing asset references remain pointed at the same outputs while the material is re-baked.

After the bake

The bake result can open the resulting Material Instance, apply it to selected actors, or run another bake. Applying to actors asks before replacing existing assigned materials.

Recipe versus Bake
Keep the Mixtormat recipe as the editable source. Treat the baked textures and Material Instance as the production-facing result.

Troubleshooting the Look

The blend looks like a flat Photoshop dissolve

Check Height before adding more mask noise. Make sure the materials have a believable relative height and use a suitable Height source.

The material looks too procedural

Separate variation by scale. Use a broad mask for placement, region IDs for per-piece variation, and only then add small surface breakup.

An effect is appearing everywhere

Give the effect a scoped mask or drive its parameters from a Layer Mask, Child Mask, or Region IDs. Placement is usually a better fix than reducing every strength control.

A child seems to be causing the wrong result

Select it and use Bypass child. If the issue disappears, inspect that child's mask or debug view before changing unrelated layers.

Fine cracks shimmer while moving the camera

Try FXAA while authoring the crack or mask. TSR can resolve thin detail better when still, but temporal history needs time to settle after movement.

The preview is too expensive while tuning

Lower Preview Quality, reduce Screen Percentage, or work at a lower composition resolution. Return to the intended final settings before judging small detail.

I cannot tell whether the mask or the effect is wrong

Use the available feature/debug preview. Inspect the region source first; then judge the effect using it.

I need the same setup in several layers

Use Copy as Instance / Paste Instance when the children should stay related. Use a normal copy when each one needs independent art direction.

I changed too many things at once

Use Before / After, solo layers, bypass the selected child, and Undo/Redo. Reduce the stack back to the first point where the material reads correctly, then reintroduce operations one at a time.
