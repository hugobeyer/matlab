P0 — Combine IDs does not actually support Breakup as an upstream producer. The editor currently says it does: HasRegionIdProducerAbove() considers Breakup valid. But GPU execution does not. AddRegionProducerPasses() runs before the child loop and only generates Cluster / Pattern / Combine IDs. Breakup publishes its IDs later in QueuePendingBreakup(). Therefore a Breakup -> Combine IDs stack cannot make Combine consume Breakup. Worse, if an older Pattern/Cluster exists above Breakup, Combine can silently consume that older map instead. This needs either a real ordering fix or Breakup must be removed from Combine's accepted-upstream logic. I would fix the execution order rather than pretend the feature isn't supported.

Fab package structure needs a real release-package audit, not a GitHub audit. Fab requires a code plugin package to contain .uplugin, Source, Content, and Config; the downloadable link must be a ZIP containing one plugin and must not require login/permission. Your repo intentionally ignores Content/ and all .uassets, so I cannot verify the actual shipping Content structure, redirectors, unused assets, paths or package size from GitHub. Fab requires no unused content/directories, cleaned redirectors, sensible English naming, and paths within its limits. Build the final ZIP from your local complete plugin, not from a GitHub source archive.
Your .uplugin itself looks mostly release-ready. 1.0.0, UE 5.8.0, Win64, docs/support URLs, Runtime/Shader/Editor module separation, CanContainContent, icon, and Lucide/Feather notices are all there.
